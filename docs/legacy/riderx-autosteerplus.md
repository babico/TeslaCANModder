## 2. Executive verdict

This repo is a commercial-style **client packaging exercise**, not a CAN research repo: a Vue 3 UI (Konsta/Tailwind) wrapped around the live `fsd.teslaandroid.com` portal, shipped as a Capacitor iOS+Android app and a Cloudflare Worker web fork. There is no firmware, no CAN frame handling, and no tests; every vehicle claim (Summon radius growth, follow-distance profile mapping, software-version compatibility) is data baked into Vue templates, not decoded from buses. The mechanisms that matter to TeslaCANModder are all **transport-side**: the Web Bluetooth shim over `@capacitor-community/bluetooth-le`, a four-characteristic GATT protocol (status/config/command/OTA-data), a well-tuned BLE OTA engine (180 B chunks, retry/backoff/shrink, tail resend, sha256+signature+IV secure handshake), and a software-version compatibility gate whose version intel (2026.2.9.x = FSD 14, 2026.8.3 = FSD 13 install-good, 2026.8.6 blocked) converges with our own `fwcompat` decoder. Adaptation candidates: the BLE OTA engine and its tuning constants, a refinement of our `fw_compat` 2026-release gating, and the follow-distance profile table as docs content (capture-first, direction unverified). Do not port: the third-party portal dependency, the committed Android keystore with a disclosed password, CapGo auto-update, the ~140 MB of committed screenshots, and the untyped 3500-line controller pattern.

### BLE OTA engine (chunk push, retry/backoff/shrink, tail resend, secure handshake)

- **Claim (README / summary):** "Authenticated Web Bluetooth OTA and device management portal" (`index.html:12`); old summary called the app a "UI/control layer" without naming the OTA protocol (git show HEAD:docs/legacy/riderx-autosteerplus.md#L58).
- **Code path:** `src/features/portal/controller.ts:3012-3081` — `installFirmware()` → `fetchFirmwarePackage()` (HTTP, 2756-2767) → `ensureSecureMetadataReady()` (2928-2959) → `ota_begin:<size>` (3043-3051) → `uploadFirmwareChunks()` (2903-2926, per-chunk `writeChunkWithRetry()` 2862-2901) → `waitForOtaBytes()` flush loop (2775-2860) → `ota_finish` (3063-3072). Abort: `abortOta()` 3083-3092.
- **Frame spec:** text handshake over command characteristic: `ota_meta:<size>:<sha256>:<signatureHex>:<deliveryIvHex>` → `ota_meta_ok:`; `ota_begin:<size>` → `ota_ready:`; binary chunks (≤180 B, ≥96 B) to `…9804` write-without-response; `ota_finish` → `ota_done:`; `ota_abort` → `ota_aborted`; errors as `ota_error:<msg>`.
- **Gates and timing:** 4 attempts per chunk, backoff 180 ms × attempt, chunk shrink 24 B per failure (16 B if the device already advanced past the offset) with floor 96 B (`2862-2901`); progress status read every 6 chunks (`2920-2922`); flush poll 200 ms, flush timeout 20 s, status heartbeat 800 ms in tail, tail grace 700 ms, tail resend limit 2, tail window 360 B (`2775-2860`); `ota_begin`/`ota_meta` timeout 8 s, `ota_finish` 15 s, abort 4 s; package size must equal announced size (`3028-3032`) and is capped at 16 MiB (`2970-2973`).
- **State machine:**

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> SecureMeta : installPackage(pkg)
    SecureMeta --> Begin : ota_meta_ok
    SecureMeta --> Error : ota_error / metadata invalid
    Begin --> Uploading : ota_begin:size -> ota_ready
    Begin --> Error : ota_error
    Uploading --> Flushing : all chunks written
    Uploading --> Uploading : retry <=4, shrink 24B, floor 96B
    Flushing --> Finalize : otaBytesWritten >= size
    Flushing --> Flushing : poll 200ms, tail resend <=2
    Flushing --> Error : 20s stall / ota_error
    Finalize --> Done : ota_finish -> ota_done
    Finalize --> Error : ota_error
    Uploading --> Aborted : ota_abort
    Flushing --> Aborted : ota_abort
    Aborted --> Idle : setUpdatingState(false)
    Error --> Idle : refreshStatus + render
    Done --> Restart : deviceWillRestart
    Restart --> [*]
```

## 12. Surface inventory and security notes

Transport surfaces:

- **BLE GATT** (native via shim, web via Web Bluetooth): discover by namePrefix, then 4 characteristics; commands `reboot`, `status`, `ota_meta:…`, `ota_begin:<size>`, `ota_finish`, `ota_abort`; config writes `hooks=0|1`, `mode=<id>`, `payload=<id>:0|1`, `setting=<id>:<value>` (controller.ts:2713-2747). Responses: `restarting`, `status_ok`, `ota_meta_ok:`, `ota_ready:`, `ota_done:`, `ota_aborted`, `ota_error:…`.
- **HTTP portal API** (all to `fsd.teslaandroid.com`, via worker proxy on web / fetch bridge on native): `session.php`, `login.php`, `logout.php`, `packages.php`, `package-download.php`, `change-password.php`, `device-context.php`, `passkeys.php`, `passkey-register-options.php`, `passkey-register-verify.php`, `passkey-auth-options.php`, `passkey-auth-verify.php`, `passkey-delete.php`, `admin-users.php`, `admin-create-user.php`, `admin-set-user-active.php`, `admin-set-user-groups.php`, `admin-delete-user.php`, `admin-sync-shopify-customers.php`, `admin-set-package-groups.php`, `admin-delete-package.php`, `admin-device-management-lock.php` — CSRF header from meta tag (controller.ts:92-98, 1564-1597).
- **Hash routes**: `#/home`, `#/docs?section=…`, `#/onboarding`, `#/faq` (controller.ts:33-36, 202-296). The `openIdentifyCar` action and `"identify"` page in the view-model are dead surfaces: no component calls them (only view-model.ts:90, 140, 197 define them).
- **Cloudflare Workers**: `asp.tslap.store` (proxy + static SPA) and `yt.tslap.store` (YouTube embed wrapper).
- **CapGo update channel**: auto-update of the native app shell on launch, channel `production`.

Provenance/security findings:

- **Committed signing keystore with disclosed password**: `android.jks` is in the tree and README:192 states "sign with android.jks the key and passwords are all: autosteerplus". Anyone can sign impersonating updates for this app id. Severity: high for upstream, irrelevant to us — never replicate.
- **Hardcoded Cloudflare account id** `9ee3d7479a3c359681e3fab2c8cb22c0` in both wrangler configs (wrangler.jsonc:5, wrangler.youtube.jsonc:5) — account-scoped identifier committed; use env/secrets instead.
- **Cross-origin cookie forwarding**: the fetch bridge rewrites same-origin URLs to the remote portal with `credentials: 'include'` (portal-session.ts:30-36, 58-82) — session cookies for the wrapper origin are silently re-sent to the third-party portal. Working as designed for this product; a pattern to avoid in our stack.
- **Auth depends on the live third-party portal** including its Turnstile CAPTCHA and CSRF rotation (index.html:16-17, 24; portal-session.ts:99-109). No local fallback; outage of `fsd.teslaandroid.com` bricks the app (README:291 acknowledges).
- **~140 MB+ of marketing binaries committed at repo root** (50.8 MB `profile_set_action_done_car_screen.png`, 48.6 MB `service_mode.png`, 39.8 MB `set_drive_profile_from_wheel.png`, 5.5 MB `fsd_in_Action.JPG`, plus per-density splash clones) — repo bloat anti-pattern.
- **`// @ts-nocheck` on the 3484-line controller** (controller.ts:1) — the load-bearing module ships with type checking disabled.
