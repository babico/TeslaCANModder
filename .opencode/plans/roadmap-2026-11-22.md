## Global Constraints

- No code copied from `legacy/` into shipping code. Independent implementation only; license and do-not-copy lists in each deep-dive doc are binding (repo-state §E; old roadmap Global Constraints).
- **Safety rule: every injection gate has exactly one authority.** AP/park/OTP-style gates must not be distributed across nodes or duplicated between firmware paths (repo-state `:81`; cross-cutting §6.1).
- Every CAN frame mutation, routing, checksum or transport-visible change requires `docs/checklists/can-review-checklist.md` **and** a listen-only bench capture before it lands (current-state §5 closing; firmware.md §7 severity note).
- Code-only agreement between upstreams is not proof. CAPTURE or TEST-READ evidence is required to flip a decode (current-state §8; cross-cutting §0).
- Commits and pushes: feature branch only, never `main`; do not force-push, reset shared history, or merge without explicit request (AGENTS.md Git workflow).
- No new artifacts under `docs/superpowers/`; plans/analysis/reports live in `.opencode/{plans,analysis,reports}/`.
- Keep the existing 191 unstaged working-tree changes out of every commit until separately reviewed (repo-state `:15`; tools-ci.md §0).
- Every task below carries an ID, acceptance test, evidence citation, rough effort and risk. New findings go to the intake file (§Findings intake), never silently into an in-flight phase.

## Findings intake

New findings go to `.opencode/analysis/findings-intake.md` with this schema (from cross-cutting.md §6.1). Register the Phase-1 items there before starting work.

```text
SC-<nnn> | source=<doc|protocol|legacy|todo|grep> | claim=<one line>
cite=<file:line> | grade=<CODE-READ|TEST-READ|CAPTURE|SUMMARY-ONLY|UNVERIFIED>
state=<IMPLEMENTED|NO_HANDLER|ABSENT|CONTRADICTION|DOC_DRIFT>
severity=<S0 safety|S1 contract|S2 doc/UX|S3 debt>
decision=<now|next|never> | rationale=<why now/next/never>
acceptance=<observable test/capture> | needs_capture=<yes|no>
effort=<S|M|L> | risk=<low|med|high> | owner=<area>
```

Triage rules:

- `now` = doc/contract truth fix or safety gate, no hardware needed (cross-cutting §6.1).
- `next` = needs bench capture, firmware change, or cross-workspace coordination.
- `never` = legacy-only idea with no shipping owner (record and close).
- Any `S0` needs `docs/checklists/can-review-checklist.md` plus a listen-only bench capture before it lands.

## Definition of done for a phase

1. Every task has a test or a measured report attached; no "looks fine" claims.
2. `npm run test:all` and `npm run lint:all` run; firmware native tests + `pio run` for affected envs; results saved under `.opencode/reports/`.
3. CAN-affecting changes have the checklist walked and a capture reference; one safety-gate authority.
4. New findings are in the intake file, not silently added to the current phase.
5. One PR per logical change; `main` only via PR; keep the 191 pre-existing unstaged changes out of commits.
