# TeslaCANModder Recovery Roadmap — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement a phase task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Turn the 99-repo research sweep into corrected, verifiable firmware and a coherent product roadmap without losing control of scope.

**Architecture:** Correctness first (capture-grounded decode fixes + documented-but-missing surfaces), then CI/hardware capacity measurement with two parallel spikes (ESP32-S3 and multi-ESP32 cluster), then the web UI rewrite on stable contracts. Research is already done in `docs/legacy/*.md`; this plan only consumes it.

**Tech Stack:** PlatformIO/C++ (ESP32 + native Unity tests), TypeScript ESM (`packages/protocol`, Expo client), Node tools, GitHub Actions, bench CAN capture via `tcm-debug`.

**Spec:** `.opencode/analysis/repo-state-2026-11-22.md`, plus `docs/legacy/*.md` (99 deep dives) and the pre-existing 105-item todo at `docs/superpowers/todo.md` (historical; read-only reference — do not add to that directory).

## Global Constraints

- No code copied from `legacy/` into shipping code. Independent implementation only; license and do-not-copy lists in each deep-dive doc are binding.
- Every CAN frame mutation, routing, checksum or transport-visible change requires `docs/checklists/can-review-checklist.md` and a listen-only bench capture before it lands.
- Code-only agreement between upstreams is not proof. CAPTURE or TEST-READ evidence is required to flip a decode.
- `git submodule update` that bumps a recorded SHA, commits, pushes, merges and PRs require explicit per-operation approval (`commit-ask-first`).
- No new artifacts under `docs/superpowers/`; plans/analysis/reports live in `.opencode/{plans,analysis,reports}/`.
- Keep the existing 191 unstaged working-tree changes out of every commit until separately reviewed.

## Review Focus

- Wrong gear/pedal field (`0x118`) feeding `apGateParked` → gate must close only on real Park; capture first.
- Wrong ALC `0x249` checksum/counter → turn-signal injection must be rejected by the vehicle, not spammed; capture first.
- BLE key role / field numbers → key provisioning must request owner/charging-manager correctly and parse session info; bench exchange with golden capture.
- Advertised command with no handler → client shows a control that silently does nothing; implement-or-deprecate explicitly.
- Web UI rewrite against a moving protocol contract → freeze wire shape before rewriting the component tree.

## Definition of done for a phase

1. Every task has a test or a measured report attached; no "looks fine" claims.
2. `npm run test:all` and `npm run lint:all` run; firmware native tests + `pio run` for affected envs.
3. CAN-affecting changes have the checklist walked and a capture reference.
4. New findings are in the intake file, not silently added to the current phase.
5. One PR per logical change; `main` only via PR.
